## videoInfo.json的格式
- **文件位置**: videoInfo.json：本 JSON 是视频的本地元数据文件，记录从 B 站获取并保存在本地的相关信息。

**标识类 (IDs & 标识)**
- **说明**: 包含用于唯一标识视频/分P/系列与用户的标识符。
  - `type`: 内容类型（示例值 `"ugc"` 表示用户生成内容）。
  - `aid`: AV 号/Archive ID（旧的或后台索引 id，用于与站内资源交互）。
  - `bvid`: B站新的全局视频 ID（字符串，公开用于分享与检索）。
  - `cid`: 分P 的内容 ID（每一分P 一个 `cid`，用于请求弹幕和分段流）。
  - `itemId` / `groupId`: 本地或应用层的分组/项目 id（表示属于哪个项目或合集）。
  - `p`: 分P 页码（第几 P），用于区分同一视频的多个分段。
  - `tabP` / `tabName`: 分区/标签页信息（例如 `tabName` = "正片" 表示这是主片）。

**作者与来源 (Source & Author)**
- **说明**: 与上传者或分组信息相关，便于显示与归属。
  - `uid`: 上传者用户 ID（字符串或数字）。
  - `uname`: 上传者用户名（用于 UI 显示）。
  - `avatar`: 上传者头像 URL。
  - `groupTitle` / `groupCoverUrl` / `groupCoverPath`: 所属合集/系列的标题与封面（远程 URL + 本地缓存路径）。

**媒体与播放 (Media & Playback)**
- **说明**: 与视频内容、质量与封面相关的信息。
  - `title`: 视频标题。
  - `coverUrl` / `coverPath`: 封面图片的远程 URL 和已保存的本地路径。
  - `duration`: 时长（单位为秒，示例 `1277` 秒 ≈ 21 分 17 秒）。
  - `codecid`: 编解码器 ID（数值代号，表示视频流使用的编码类型，平台内部定义，例如常见用于区分 H.264/AV1 等）。
  - `qn`: 清晰度码（质量等级代码，B 站使用数值表示不同分辨率/码率，客户端据此请求不同清晰度）。
  - `allowHEVC`: 布尔值，是否允许 HEVC（H.265）编码流。

**统计与元数据 (Stats & Meta)**
- **说明**: 播放、弹幕、发布时间等用于展示与排序的数据。
  - `danmaku`: 弹幕数量（整数）。
  - `view`: 播放/浏览量（整数）。
  - `pubdate`: 发布时间（Unix 时间戳，单位为秒；可转换为可读日期）。
  - `status`: 状态字符串（例如 `"completed"`，在本地上下文可能表示下载或元数据采集完成）。
  - `isCheese`: 平台/应用特定标志（布尔值或标识，表示特殊分类，含义取决于客户端逻辑）。

**下载与本地存储 (Download & Local Files)**
- **说明**: 本地下载状态、大小与路径，便于断点续传与 UI 展示。
  - `totalSize`: 总字节数（视频文件总大小，单位字节）。
  - `loadedSize`: 已下载的字节数（单位字节）。
  - `reportedSize`: 向外报告的大小（可能用于 UI 显示或与远端校验）。
  - `progress`: 下载进度（百分比，示例 `100` 表示完成）。
  - `speed`: 当前或最近一次记录的下载速度（单位依实现而定，通常字节/秒）。
  - `loaded`: 布尔值，表示是否已完成下载并保存到本地。
  - `completionTime`: 完成时间（通常为 Unix 时间戳的毫秒表示，表示何时完成下载或处理）。
  - `coverPath` / `groupCoverPath`: 已保存的封面本地路径（便于离线显示）。

**时间戳字段 (Timestamps)**
- **说明**: 多为毫秒级或秒级的时间戳，用于记录创建/更新/完成时间。
  - `createTime`: 记录创建时间（通常为毫秒级 Unix 时间戳）。
  - `updateTime`: 最近更新时间（毫秒级）。
  - `completionTime`: 完成处理/下载时间（毫秒级）。
  - 说明：若需要将这些值转换为可读日期，可将毫秒除以 1000 得到秒，再转换为常见日期格式。

**状态标志 (Flags)**
- **说明**: 用于控制 UI/流程的布尔/状态字段。
  - `active`: 布尔，表示条目是否处于活跃/选中/可用状态（取决于客户端含义）。
  - `loaded`: 已下载完毕的标志（与 `progress`/`loadedSize` 相关）。
  - `status`: 可复用的状态字段（例如 `"completed"`、`"downloading"` 等，具体含义由程序约定）。


## 缓存视频集合识别逻辑

BiliTools 采用智能的集合识别机制，自动将相关的缓存视频组织成逻辑组，支持 B 站官方合集和多 P 视频的自动分组。

### 集合判定规则

系统以 **groupID** 为主要判断依据，通过以下规则判断视频是否属于集合：

```
核心规则（最根本的判断）：
- 有其他视频共享相同的 group_id → 属于集合

辅助规则：
- p > 1 → 属于集合（多P视频）
- 没有其他视频共享 group_id 且 p = 1 → 不属于集合（独立视频）
```

**判断逻辑：**
1. **首先检查 groupID**：如果有其他视频与当前视频共享相同的 `group_id`，则该视频属于集合
2. **其次检查分P**：如果没有共享 groupID 但 `p > 1`，则该视频属于多P集合
3. **默认为独立**：其他情况均为独立视频

**字段说明：**
- **p** - 分P序号，表示视频的第几分P，默认为 1
- **group_id** - 官方合集的标识符，来自 videoInfo.json 的 `groupId` 字段
- **bvid** - 视频的 BV 号，B 站新的全局视频 ID

### 分组键获取规则

当视频被判定为属于集合时，系统按以下优先级获取分组键：

1. **优先使用 groupId**（官方合集）
   - 条件：有其他视频共享相同的 group_id
   - 用途：将同一官方合集的所有视频分组在一起
   - 示例：合集内的多个视频共享同一个 groupId（无论 groupId 是否等于 bvid）

2. **其次使用 bvid**（多P视频）
   - 条件：p > 1
   - 用途：将同一视频的多个分P分组在一起
   - 示例：某视频的第1P、第2P、第3P 共享同一个 bvid

3. **不分组**
   - 条件：既不是官方合集也不是多P视频
   - 结果：作为单个视频显示

### 组的构建规则

- **最小组大小**：至少需要 2 个视频才能形成一个组
- **单个视频处理**：如果某个分组键只有 1 个视频，则该视频作为单个视频显示，不形成组
- **视频排序**：组内视频按 p（分P序号）升序排列

### 组信息生成

| 信息 | 生成规则 |
|------|--------|
| **组标题** | 优先使用 `groupTitle` 字段（来自 videoInfo.json），否则从组内视频标题提取公共前缀 |
| **组封面** | 优先级：group.jpg > group.png > image.jpg > image.png > 第一个视频的封面 |
| **UP主** | 统计组内所有视频的 UP 主，若某个 UP 主占比 > 70% 则使用该 UP 主，否则显示"多个UP主" |
| **统计信息** | 计算组内视频的总数、总时长、总文件大小、最新下载时间 |

### 显示项类型

前端缓存列表中显示两种类型的项目：

- **VideoGroup** - 包含 2 个或以上视频的组
  - 可展开/折叠查看组内视频
  - 显示组的聚合信息（标题、封面、UP主、视频数等）
  - 支持对整个组进行操作（打开文件夹、删除等）

- **SingleVideo** - 单个视频
  - 不属于任何组的独立视频
  - 显示视频的完整信息

### 组状态管理

- **展开/折叠状态**：每个组的展开/折叠状态持久化到数据库
- **状态切换**：支持切换、设置、获取组的展开状态
- **状态清理**：支持清理孤立的组状态记录（当组被删除时）

### 实现细节

**后端处理流程：**
1. 从数据库读取所有缓存记录
2. 遍历每条记录，判断是否属于集合
3. 对属于集合的记录，获取其分组键
4. 按分组键将记录分组，过滤掉只有 1 个视频的组
5. 为每个组生成聚合信息（标题、封面、UP主等）
6. 返回混合的显示项列表（组和单个视频）

**前端展示流程：**
1. 接收后端返回的显示项列表
2. 根据项目类型渲染为组卡片或单个视频卡片
3. 从数据库加载每个组的展开状态
4. 支持用户交互（展开/折叠、选择、删除等）

### 使用场景示例

**场景 1：官方合集**
```
合集 ID: 123456
├─ 视频 1 (p=1, groupId=123456, bvid=BV1xxx)
├─ 视频 2 (p=1, groupId=123456, bvid=BV2xxx)
└─ 视频 3 (p=1, groupId=123456, bvid=BV3xxx)
```
→ 识别为一个组，groupId 为 123456

**场景 2：多P视频**
```
视频 BV1xxx
├─ 第 1P (p=1, bvid=BV1xxx)
├─ 第 2P (p=2, bvid=BV1xxx)
└─ 第 3P (p=3, bvid=BV1xxx)
```
→ 识别为一个组，bvid 为 BV1xxx

**场景 3：混合场景**
```
合集 ID: 123456
├─ 视频 A (p=1, groupId=123456, bvid=BVaaa) - 多P视频
│  ├─ 第 1P (p=1, bvid=BVaaa)
│  ├─ 第 2P (p=2, bvid=BVaaa)
│  └─ 第 3P (p=3, bvid=BVaaa)
└─ 视频 B (p=1, groupId=123456, bvid=BVbbb) - 单P视频
```
→ 识别为一个合集组（groupId=123456），包含 4 个视频

**场景 4：单个视频**
```
视频 (p=1, groupId=BVxxx, bvid=BVxxx)
```
→ 不识别为组，作为单个视频显示
